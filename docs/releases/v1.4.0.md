# Fenced v1.4.0 Release Notes

**Release Date:** October 20, 2026  
**Git Tag:** `v1.4.0`  
**Status:** General Availability (GA)  
**Product Version:** `1.4.0.0` (SemVer `1.4.0`)

Fenced v1.4.0 is a consolidation release. It adds the second model protocol
the gateway can speak, gives the Agent Runtime Interface a single written
contract, and moves several large files and packages into a shape that can be
reviewed, extended and governed.

Nothing in this release changes the frozen public contracts, and no public
identifier was renamed. The compatibility window for the pre-rename
`v1alpha1` surface remains open until **2027-02-17**.

---

## 1. What's New in v1.4.0

### 1.1 The Anthropic Messages Protocol in the Model Gateway
The Model Gateway speaks two wire dialects now. A provider selects the dialect
in the `-model-providers` file:

```json
{
  "providers": [
    {"name": "deepseek", "baseUrl": "https://api.deepseek.com/v1", "apiKeyEnv": "DEEPSEEK_API_KEY"},
    {"name": "anthropic", "baseUrl": "https://api.anthropic.com", "apiKeyEnv": "ANTHROPIC_API_KEY", "protocol": "anthropic"}
  ],
  "routes": [{"modelRef": "logical/claude", "provider": "anthropic", "model": "claude-sonnet-4-5"}]
}
```

The OpenAI-compatible dialect stays the default, so existing configurations
keep their meaning. Both dialects share the same guarantees - budget
reservation, exact provider-reported usage settlement, provider request-id
capture, bounded retries, per-provider circuit breaking - and the Anthropic
dialect translates only the wire shape: the top-level system prompt, the
required `max_tokens`, the `tool_use` and `tool_result` content blocks, the
typed server-sent events and the stop reasons.

The developer CLI streams through the same layer, so a protocol change lands
in one place, and the provider's reasoning channel is delivered separately
from the answer.

### 1.2 One Written Contract for the Runtime Interface
The Go SDK, the Python SDK and the OpenAPI specification each described the
Agent Runtime Interface on their own. They now share the golden vectors in
`sdk/conformance/fixtures/runtime-interface-v1.json`: for every endpoint, the
request, the status code, the fields the response must carry and the values it
must hold.

The vectors are executed against the Go host, against the Python host and
checked against the published schema. A renamed field, a changed status code
or a status value outside the vocabulary fails on every side at once.

### 1.3 One Transport Policy
The Runtime Interface transport policy - plaintext only on loopback, HTTPS
with server verification everywhere else - had two implementations: one in the
adapter library and one in the adapter command line. The command line now
delegates, and the rule lives in `internal/runtime/bindings` with the binding
table it guards. The development escape hatch
(`-allow-plaintext-remote-runtime`) applies to the runtime binding table; an
explicit `-adapter-endpoint` always requires HTTPS or loopback.

### 1.4 A Tool Grant That Pins a Version Now Works
A tool capability grant of the form `name@version` or `name@*` was visible to
the publish-time tool freeze but not to the runtime capability check, which
compares bare tool names. A correctly pinned publication was therefore denied
every agent-facing tool call - including the two manifests shipped in
`examples/`. Publications now carry the two vocabularies apart:
`capabilities.tools` holds the tool names, and the derived
`capabilities.toolVersions` holds the pinned and floating grants. Publications
written before the split keep working, and no migration is required.

### 1.5 Structure That Can Be Reviewed
| Before | After |
| --- | --- |
| `cmd/agent/ui.go`, 3483 lines | entry point, handlers, and the console document as an asset |
| `internal/control/api/handler.go`, 1997 lines | one file per resource, `handler.go` keeps the assembly |
| `internal/runtime/adapter/worker.go`, 956 lines | five files by concern, plus two packages for the binding table and the brokers |
| one model client in the CLI, one in the gateway | one dialect implementation |

The adapter worker no longer depends on the generated protocol packages, the
model and memory gateways or the MCP contract; the twenty-four adapter test
cases and the sixteen observable Control API endpoints are unchanged.

### 1.6 The Rename, Completed
The mechanical rename covered the connected `AgentOS`, `agentos` and `AGENTOS`
forms and left the two-word `Agent OS` behind in the runtime log messages, the
package documentation, the Rego and TLA+ headers, the OpenAPI titles and the
JetStream stream description. Those now read `Fenced`. No identifier, protocol
name, field number or persisted value changed: the JetStream stream name
(`FENCED_EVENTS`), the event subject prefix (`fenced.events`) and the database
contents were already renamed, and `docs/NAMING.md` now records them as
frozen.

### 1.7 Working With the Repository
`AGENTS.md` describes the repository map, the verification ladder from a
seconds-long unit test to the full acceptance suites, the rules that must not
be broken and the traps that cost time in practice. The `Makefile` mirrors the
CI gates as local targets:

```bash
make verify           # formatting, vet, unit tests, the Python SDK, the version
make conformance      # the Runtime Interface certification suite
make takeover-check   # the fencing takeover, against a real PostgreSQL
make dev-up           # the local control plane
```

## 2. Frozen Stable Public Contracts

All interfaces below remain frozen against breaking changes, as specified in
the [v1.2 Contract Freeze](../contracts/v1.2-contract-freeze.md):

| Subsystem | Frozen Version | Definition |
| --- | --- | --- |
| Kubernetes-style API group | `fenced.dev/v1` | `proto/fenced/` |
| Runtime Protocol | `fenced.runtime.v1` | `proto/fenced/runtime/v1/` |
| Runtime Interface | `fenced.runtime.interface/v1` | `api/openapi/runtime-interface-v1.yaml` |
| Control API | `v1` | `api/openapi/control-v1.yaml` |
| Syscall ABI | `1.0.0` | `proto/fenced/syscall/v1/` |
| Gateway / Model / IPC / Effect / Service protocols | `fenced.*.v1` | `proto/fenced/` |

The v1.4.0 release adds no new syscall number, changes no field number and
renames no protocol identifier. The Anthropic dialect is selected inside the
existing model execution layer and does not alter the Model Protocol contract.

The pre-rename `v1alpha1` surface remains accepted until **2027-02-17**.

## 3. Quality and Reliability Evidence

The changes in this release were verified against the running product, not
only against unit tests:

- **Fencing takeover**: a worker was killed with `SIGKILL` during an
  execution; the lease expired, the recovery controller created a replacement
  attempt with a higher fencing token, and the task completed. The audit
  ledger recorded the takeover, the token upgrade, the checkpoint and the
  result.
- **Anthropic end to end**: the gateway called an Anthropic Messages
  endpoint, translated a `tool_use` block into a kernel tool call, the agent
  executed the tool, returned the result as a `tool_result` block and the
  second model call produced the answer. The settled token count equalled the
  provider-reported usage exactly.
- **Control API**: the sixteen observable endpoints were captured before and
  after the file split and compare equal.
- **Runtime Interface**: the shared vectors run green on the Go host, on the
  Python host and against the published schema.
- The CI gate is unchanged: formatting, `go vet`, staticcheck, govulncheck,
  the race-enabled unit and integration suites, the Python and TypeScript SDK
  suites, the Rust provider checks and the contract drift guards.

## 4. Upgrade and Migration Guide

### 4.1 Upgrading from v1.3.0 to v1.4.0

No public identifier changed, so an upgrade is a version bump:

```bash
# Helm
helm upgrade --install fenced deploy/helm/fenced --version 1.4.0 \
  --set image.tag=1.4.0 -f your-values.yaml

# Or a release artifact
gh release download v1.4.0 --repo CloudEdgeCore/Fenced
```

Apply the migrations before the new binaries start:

```bash
fenced migrate -database-url "$DATABASE_URL"
```

### 4.2 If you use a model provider
Nothing changes for an OpenAI-compatible provider. To use an Anthropic
endpoint, declare the protocol on that provider entry and route a model
reference to it. The provider key is still read from the environment variable
the entry names, and it still never reaches the agent.

### 4.3 If you publish agent versions
A tool grant may now be written as `name`, `name@version` or `name@*`. A
pinned grant grants the tool and pins the version the freeze allows; a
floating grant grants the tool and accepts version drift. The published
document gains one derived field, `capabilities.toolVersions`; the
`specDigest` of a publication therefore differs from the digest of the same
manifest published under v1.3.0.

### 4.4 If you operate the adapter worker
The development escape hatch keeps its scope: it relaxes the runtime binding
table, not the explicit `-adapter-endpoint`. An explicit endpoint is
validated by the library now, which also rejects a URL that carries a query,
a fragment, userinfo or a path.

### 4.5 Compatibility window
The pre-rename identifiers - the `agentos` command, the `AGENTOS_*`
environment variables, the `X-Agentos-Execution` header and the `agentos.*`
protocol identifiers - remain accepted until **2027-02-17**. See
[`docs/NAMING.md`](../NAMING.md) and [`docs/COMPATIBILITY.md`](../COMPATIBILITY.md).
