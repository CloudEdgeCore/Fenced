# Fenced v1.2.0 Release Notes (LTS)

**Release Date:** September 29, 2026  
**Git Tag:** `v1.2.0`  
**Status:** Long-Term Support (LTS) / General Availability (GA)

Fenced v1.2.0 is a major milestone release transforming Fenced from a single-attempt task scheduler into a comprehensive, multi-tenant **Agent Operating System Kernel**. 

This release introduces the **Agent Process System**, **Supervisor Engine**, **Syscall ABI 1.0.0**, **Durable IPC Mailbox**, **External Effect Engine**, **Conformance Certification Kit**, and native support for **5 major agent frameworks** (LangGraph, AutoGen, CrewAI, OpenAI Agents SDK, and Custom Agents).

---

## 1. What's New in v1.2.0

### 1.1 Dual-Model Process System
Fenced now provides native operating system abstractions for two distinct workload topologies:
1. **Task Processes (Ephemeral)**: `Task → Run → Attempt` state machine for batch jobs, goal-directed planning, and analytical workflows. Non-preemptible execution with cooperative cancellation.
2. **Daemon Services (Long-Running)**: `AgentService → AgentInstance` for persistent agents, event listeners, webhook workers, and autonomous crews.

### 1.2 Supervisor Engine & High Availability
- **Self-Healing**: Automatic failure detection and restart with exponential backoff and jitter.
- **Heartbeat Auto-Reap**: When an instance misses heartbeats past its TTL, the supervisor fences the zombie instance and launches a replacement.
- **Rolling Upgrades**: Zero-downtime version rollouts enforcing `max_surge` and `max_unavailable` constraints.
- **Graceful Draining**: Existing requests and tasks complete gracefully before instance termination.
- **Automated Rollback**: Automatic fleet rollback if new version instances fail health checks within `min_ready_seconds`.

### 1.3 Syscall ABI 1.0.0
A frozen, POSIX-modeled system call interface (`proto/fenced/syscall/v1/syscall.proto`) decoupling agent runtimes from kernel internals across 8 subsystems:
- **Tool Subsystem** (`SYS_TOOL_INVOKE`, `SYS_TOOL_LIST`)
- **Model Subsystem** (`SYS_MODEL_INVOKE`, `SYS_MODEL_BEGIN`, `SYS_MODEL_SETTLE`, `SYS_MODEL_FINISH`)
- **Memory Subsystem** (`SYS_MEMORY_PUT`, `SYS_MEMORY_SEARCH`)
- **IPC Subsystem** (`SYS_IPC_SEND`, `SYS_IPC_RECEIVE`, `SYS_IPC_ACK`)
- **Runtime Subsystem** (`SYS_RUNTIME_CHECKPOINT`, `SYS_RUNTIME_COMPLETE`, `SYS_RUNTIME_YIELD`)
- **Service Subsystem** (`SYS_SERVICE_HEARTBEAT`, `SYS_SERVICE_QUERY`)
- **Resource Subsystem** (`SYS_NAMESPACE_GET`, `SYS_RESOURCE_QUOTA_GET`, `SYS_RESOURCE_USAGE_GET`)
- **Effect Subsystem** (`SYS_EFFECT_EXECUTE`, `SYS_EFFECT_GET`)

### 1.4 Durable IPC Mailbox Subsystem
- Cross-agent, cross-framework asynchronous message delivery.
- Messages bound to logical run IDs, surviving attempt crashes and node migrations.
- End-to-end correlation tracking, reply-to routing, and receiver deduplication receipts.

### 1.5 External Effect Engine
- Guarantees isolation for non-deterministic and irreversible side-effects.
- **Monotonic Lease Fencing**: Stale worker attempts evicted during network partitions cannot dispatch duplicate external mutations (`SYSCALL_EFENCE`).
- **Idempotency Protection**: SHA-256 payload integrity check with automatic cached receipt replay.
- **UNKNOWN State Non-Replay Guarantee**: Ambiguous network drops or timeouts transition to `UNKNOWN` (`SYSCALL_EUNKNOWN`), strictly prohibiting unsafe automated retries.

### 1.6 Conformance Certification Kit
A single-command verification suite allowing any third-party framework or runtime adapter to certify compliance with the Fenced Kernel:
```bash
fenced conformance -endpoint http://127.0.0.1:8088
# Output: Fenced Compatible = PASS
```

### 1.7 Multi-Framework Ecosystem Support
Out-of-the-box verified adapters and reference servers for:
- **LangGraph**: StateGraph lifecycle and checkpoint synchronization.
- **AutoGen**: Multi-agent group chats routed over the Durable IPC Mailbox.
- **CrewAI**: Autonomous crews running as supervised Daemon Services.
- **OpenAI Agents SDK**: Handoffs, function calling, and cryptographic audit receipts.
- **Custom In-House Agents**: Pure Python/Go/Rust adapter via standard Runtime Protocol.

## 4. Upgrade & Migration Guide

### Upgrading from v1.1.0 to v1.2.0
1. **Database Schema**: Apply the latest PostgreSQL migrations (`internal/kernel/store/postgres/migrations`). The migration is non-destructive and backward compatible with existing v1.0 and v1.1 task tables.
2. **SDK Updates**:
   - Python: Upgrade `fenced-runtime` to `>= 1.2.0`.
   - TypeScript: Upgrade `@fenced/sdk` to `>= 1.2.0`.
   - Go: Update `github.com/CloudEdgeCore/Fenced` module reference.
3. **Existing Agents**: All existing `fenced.dev/v1` agent manifests and runtime adapters continue to run unchanged without code modifications.
